# Кодбук разметки изображений винограда

## Единица разметки и метки

Одна задача — одна фотография. В Label Studio используются два инструмента.

- `grape_cluster` — полигон по видимому контуру одной виноградной грозди. Инструмент `PolygonLabels`.
- `berry` — одна ключевая точка в центре видимой части отдельной ягоды винограда. Инструмент `KeyPointLabels`.

Один снимок может содержать несколько полигонов и точек.

## Как размечать

1. Обведите видимый контур каждой различимой грозди. Ведите полигон по границе ягод и старайтесь исключать фон, листья и ветки. Для грозди, обрезанной краем кадра, проведите границу по краю кадра. Закрытые части не достраивайте.
2. Если грозди соприкасаются или перекрываются, обведите их по отдельности там, где можете уверенно различить границы. Если граница неразличима, зафиксируйте спорный участок.
3. Поставьте по одной точке на каждую различимую ягоду. Для частично закрытой ягоды поставьте точку внутри видимой части, примерно в её центре. Если отдельную ягоду невозможно уверенно отличить от соседних, оставьте участок без точки и зафиксируйте причину.
4. Перед отправкой проверьте, что полигоны замкнуты, каждая точка стоит на ягоде и у одной ягоды нет двух точек.

## Примеры

- Две различимые грозди на одном снимке → два полигона `grape_cluster` и по точке `berry` на каждую различимую ягоду.
- Лист закрывает часть грозди → обводим видимую область и ставим точки там, где видны отдельные ягоды.
- На снимке видна отдельная ягода без различимой грозди → ставим точку `berry`.

## Независимая разметка и согласование

Оба аннотатора независимо размечают одни и те же снимки. Для каждого снимка фиксируют имя исходного файла или общий идентификатор, аннотатора, время разметки без перерывов и спорные участки. Первичные экспорты хранят в подпапке `images/` каждого аннотатора.

До согласования сравниваем пары разметок по одному и тому же изображению. Для сопоставленных полигонов можно измерить IoU, для точек — расстояние между отметками после сопоставления ягод. Правила сопоставления и пороги фиксируем до расчёта, а объекты без пары учитываем отдельно. После обсуждения сохраняем согласованную разметку в `annotations/agreed/images/` и записываем решения по спорным участкам.
